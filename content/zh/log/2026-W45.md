## 一、真正的故障原因已经找到

看这两行：

```
19:49:37 Starting fcitx5 5.1.23
19:49:37 Running inside flatpak.
```

这证明了一个重要事实：

GNOME 自动启动成功

我们的 `fcitx5-flatpak.desktop` 确实被 GNOME 执行了。

但是紧接着出现：

```
Failed to create addon: dbus
Unable to request dbus name.
Is there another fcitx already running?
```

这就是故障所在。

实际启动顺序是：

1. Ubuntu 的 `im-config` 启动原生 Fcitx5。
  
2. GNOME 自动启动文件启动 Flatpak Fcitx5。
  
3. Flatpak Fcitx5 尝试申请 D-Bus 服务名称。
  
4. 原生 Fcitx5 已经占用了这个名称。
  
5. Flatpak 的 D-Bus 插件加载失败，随后其他组件也被卸载。
  

所以我们之前的判断需要修正：不是 GNOME 没有执行自动启动，而是两个 Fcitx5 实例发生了冲突。

这也解释了为什么手动关闭原生版、启动 Flatpak 版之后，一切就恢复正常。

## 二、下一步：阻止 im-config 启动原生版

我们不需要删除原生 Fcitx5 主程序，也不需要删除 GTK、Qt 前端。

需要调整的是 `im-config` 的启动职责，让它不再启动输入法守护进程，由 GNOME 的 Flatpak 自动启动文件负责启动。

Ubuntu 的 `im-config` 支持 `none` 模式，用来停止由它启动输入法框架。相关说明见 [Ubuntu im-config 手册](https://manpages.ubuntu.com/manpages/jammy/man8/im-config.8.html?utm_source=chatgpt.com) 和 [Fcitx5 官方配置指南](https://fcitx-im.org/wiki/Setup_Fcitx_5?utm_source=chatgpt.com)。

不过，我们先检查 Ubuntu 22.04 当前安装版本是否提供这个选项。

执行：

```
im-config -l
```

再执行：

```
im-config -s -n none
```

第二条是模拟操作，不会修改配置。
